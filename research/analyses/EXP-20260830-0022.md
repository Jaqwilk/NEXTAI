## INTERPRETATION

Usunięcie gotowej sekwencji programu i trace supervision ujawniło lukę, którą EXP-0013 ukrywał. Continuous latent fitting często znalazł program zgodny z pojedynczą odpowiedzią testową, lecz niemal nigdy nie odzyskał prawdziwej dynamiki, a przy niewidzianej długości D=6 popełnił dwa błędy na szesnaście. To spełnia prerejestrowany negatywny warunek exact program induction oraz length extrapolation.

Pełne MDL pokazuje, że dane są wystarczające mimo jednego błędnego labelu: dokładnie ta sama klasa priorytetów i supports pozwala odzyskać każdy program. Nie jest to jednak skalowalny następca — sukces pochodzi z kompletnego przeszukania zamkniętej przestrzeni 256 maszyn. Learned VM nie amortyzowała tego wyszukiwania; zużyła prawie pięć razy więcej zimnej pracy i dała gorszy program.

K-niezależny warm execution jest prawdziwym, ale klasycznym efektem kompilacji i sentinel-addressed memory. Obie ścieżki muszą nadal sparsować pełny support fingerprint, a update ponownie wykonuje kosztowną indukcję. Wynik pozostaje zgodny z prior art: NPI korzystał z bogatych trace labels, differentiable Forth ze szkicu, RobustFill wskazywał zależną od zadania przewagę jawnej syntezy nad indukcją, a DreamCoder jawnie ponosi koszt search i library learning (SRC-0039–SRC-0042).

## CONFIDENCE

- `0.995` dla zapisanych accuracy, ops, bytes, memory reads, hashy, czasu i integralności, z wyłączeniem jawnie wadliwego pola program-evaluations learned VM.
- `0.99` dla stwierdzenia, że bieżąca learned VM nie odzyskuje programów: exact recovery to `11/48`, w tym `0/16` dla D=6.
- `0.99` dla dominacji przez MDL na zarejestrowanych exact osiach; kontrola ma wyższą capability, `4.751×` mniej cold ops, ten sam warm/access cost, mniej state, fit i update.
- `0.98` dla prerejestrowanej decyzji negative/null oraz braku podstaw do strojenia tego toy.
- `0.30` dla uogólnienia na inne differentiable interpreters: optimizer, liczba stanów, curriculum i learned proposal distributions mogą radykalnie zmienić wynik.
- `<0.05` dla wniosku o programowaniu ogólnym, języku albo następcy LLM.

## ALTERNATIVE EXPLANATIONS

- Osiemdziesiąt kroków gradientowych, inicjalizacja i greedy bit repair mogą być niewystarczające. Inny optimizer może zwiększyć exact recovery, ale byłby nową implementacją; nie zmieni faktu, że obecny prerejestrowany kandydat przegrał z pełnym MDL i nie może być dostrajany po wyniku.
- Klasa wszystkich dwu-stanowych binarnych Mealy machines jest silnym ręcznym priorem. MDL nie odkrywa języka programowania, a learned candidate także optymalizuje dokładnie osiem z góry określonych parametrów.
- Generator celowo wybiera tasks z unikalnym minimum mimo szumu. To ułatwia MDL, ale identyczny prior oraz supports są dostępne learned path; test rozdziela optimizer od braku informacji.
- Binarna pojedyncza odpowiedź ma wysokie prawdopodobieństwo zgodności wielu błędnych programów. Dlatego answer accuracy `0.9375` przecenia capability; exact program recovery i D=6 są ważniejszymi kryteriami.
- Dense random-feature control może być zbyt słaby dla meta-generalizacji recurrent dynamics. Nie jest górnym ograniczeniem dla transformerów lub trenowanych RNN; exact MDL jest właściwą kontrolą rozstrzygającą.
- K jednocześnie zwiększa meta-corpus i padding pamięci. Zerowy slope MDL/latent pokazuje tylko odporność na te konkretne irrelevancies; przestrzeń 256 programów i support size pozostają stałe.
- Jeden seed, widoczny generator, deterministyczna pozycja szumu i manualne operation proxies ograniczają trafność zewnętrzną. Wilson intervals nie obejmują wariancji między światami.

## DECISION

`discard` dla bieżącej differentiable latent-state VM i `dormant` dla HYP-0009 z confidence `0.14`. Exact program induction `11/48`, D=6 `14/16` oraz pełna dominacja przez exact MDL spełniają oba prerejestrowane kill rules. Zachować EXP-0013 jako dowód, że gotowe instrukcje można wykonywać tanio, oraz EXP-0022 jako dowód, że ten efekt nie przetrwał usunięcia programu i trace supervision. Nie stroić optimizerów, nie korygować licznika w chronionym wyniku i nie powtarzać score.

HYP-0012 pozostaje `testing` i rośnie ostrożnie z `0.71` do `0.73`: sparse active-prefix execution ma zerowy K slope, lecz wiarygodne zdobycie programu kosztowało pełne search `~128k` ops, learned approximation była `4.75×` droższa i niedokładna, a dense raw input miał dodatni K slope. HYP-0011 pozostaje `uncertain` przy `0.40`: exact support caching ponownie obniżył warm work o trzy rzędy wielkości, ale był to exact-repeat fingerprint, nie cross-structure reuse, a update kosztował tyle co ponowna synteza.

## NEXT DISCRIMINATING EXPERIMENT

Przejść do HYP-0011 w nowej kohorcie `semantic_trace_compilation_v1`, bez kolejnego strojenia program induction. Użyć duplicate-free, bajtowo różnych, lecz strukturalnie równoważnych DAG-ów lub planów. Learned canonical compiler powinien po rozwiązaniu jednego grafu przenosić zweryfikowany ślad na nowy izomorficzny graf bez exact-key hit; następnie lokalna zmiana jednej zależności musi unieważnić wyłącznie dotknięte fragmenty.

Porównać random, exact-key cache, standardowy indexed dynamic-programming planner, learned canonical trace compiler i oracle canonicalizer. Naliczanie musi obejmować canonicalization/routing, cold i warm execution, cache state, fit, liczbę invalidated entries, update oraz ponowną walidację. HYP-0011 obniżyć lub przenieść do dormant, jeśli nie ma cross-structure oszczędności ponad zwykły planner albo lokalna zmiana wymaga globalnej invalidacji; dodatni quick jedynie uzasadnia trzy-seed adversarial screen.
